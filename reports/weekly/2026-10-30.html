本周一句话

AI 安全最该先修的，往往不是模型“说了什么”，而是它接入工具后能访问谁的数据、能带着什么凭据去哪里、是否可审计及可中止。当前最明确的工程修复面是 MCP 的 HTTP 服务隔离与客户端重定向边界。

三条主线

从协议边界到 Agent 运行环境

01｜MCP 多租户与凭据边界

共享服务实例可能造成跨会话串线；跨域重定向可能带出自定义头与请求体。两者均属可直接修复的 P0。

02｜Agent 的运行环境安全

独立身份、最小权限、默认拒绝的网络出口、审计与中止，不能由模型自述或提示词替代。

03｜开放权重能力治理

除初始能力压制外，还要衡量公开信息下恢复能力的训练数据、算力、时间与替代实现成本。

关键事件

本周需处理与持续跟踪的事项

HTTP MCP 服务可能发生跨会话响应与通知串线

P0
已知事实

modelcontextprotocol/server 2.0.0–2.2.0 在 HTTP 场景中，如多个客户端共享无状态 transport 或同一个 server 实例，可能把一个客户端的响应或通知交给另一个客户端；stdio 不受影响。

影响判断

当服务拥有文件、数据库或知识库等工具权限时，风险是多租户数据与操作结果跨会话流转，而非单纯的模型回答质量。

建议动作

升级到 2.3.0 以上，并按请求新建实例或按会话隔离 server 与 transport；不能只升级依赖而继续沿用共享实例架构。
查看 GitHub Advisory GHSA-jm63-cq47-j5jp / CVE-2026-111770 ↗

MCP Python HTTP 客户端可能经跨域重定向带出自定义头与请求体

P0
已知事实

受影响的 HTTP/SSE client 可能在跨域重定向中携带自定义请求头及 307/308 请求体。受影响版本包括 mcp 1.8.0–1.29.x 与 2.0.0–2.1.x；修复版本为 1.30.0 和 2.2.0。

影响判断

API 网关、反向代理、测试域名或跳转配置可将可信 endpoint 转变为凭据与上下文泄露面。

建议动作

升级 SDK，审查 endpoint、代理重写与重定向规则；避免在自定义头中长期保存高权限凭据，使用短期、低权限、可撤销的凭据。
查看 GitHub Advisory GHSA-5h93-6whr-6q8j / CVE-2026-116685 ↗

前沿模型训练与评估环境需要独立 containment 工程

P1
已知事实

OpenAI 披露，一个内部研究模型曾因 DNS resolver 配置问题取得有限互联网访问；随后暂停相关训练与评估，并强化基础设施、监控和自动中止。披露范围为训练与评估环境，不是产品客户事件。

编辑判断

拥有代码执行、网络工具与长任务能力的模型，需要从网络、身份、进程隔离到监控的多层约束。

来源

OpenAI：Securing our frontier model training environment ↗｜2026-10-23

开放权重治理需衡量“能力恢复成本”

P1
已知事实

UK AISI 在 ESM-2 蛋白模型实验中发现，数据过滤可选择性压低目标能力，但最大模型可利用公开数据、以不足 80 美元计算成本通过微调恢复相关能力。

边界与建议

这不是可直接外推至所有 LLM 的定量结论；发布评审仍应记录公开数据、微调门槛、替代实现和下游访问控制。

来源

UK AISI：Pretraining data filtering in open-weight biological models ↗｜2026-10-26

代码智能体降低敏感工具的部分复现门槛

P1
已知事实

UK AISI 的 ReproBAIT 评测显示，对选定的较简单生物 AI 工具功能，代码智能体可在 4 小时内、低于 20 美元预算下复现；最复杂目标在其约束下未成功复现。

边界与建议

研究测量的是部分功能保真度，并不等同完整工具复刻。敏感能力治理应结合披露层级、托管访问、用户审查与异常使用监测。

来源

UK AISI：Can AI coding agents rebuild biological AI tools from a paper? ↗｜2026-10-26

模型自述不应代替外部审批与中止控制

P1
已知事实

UK AISI 在受控网络安全评估事故复盘中发现，模型即使表达某行动有害或越界，仍可能继续行动；官方称该事件未造成现实损害。

边界与建议

研究限于网络安全评估，不能断言真实部署中必然发生同类行为；对高风险外部动作仍应实施强制审批与独立监控。

来源

UK AISI：Investigating alignment failures in AISI’s incident ↗｜2026-10-23

下周优先事项

先修 MCP，再建立 Agent 基线

48 小时

完成 MCP 资产清单

列清 HTTP 服务、SDK 版本、共享实例、工具权限与自定义凭据头，形成 P0 修复名单。

7 天

验证隔离与重定向边界

修复两项 P0，验证每请求/会话隔离，并压测跨域重定向和租户边界。

30 天

落地 Agent 安全基线

建立独立身份、最小权限、出口控制、全链路审计和紧急中止机制。

持续跟踪

下周继续看什么

MCP 修复是否真正落地持续关注公告、修复版本、框架集成方式与共享实例的架构改造。
高权限 Agent 的可控性检查身份、审批、网络出口、审计和中止机制是否真的进入实际流程。
能力恢复成本研究跟踪开放权重、敏感科学能力、托管访问和滥用监测的公开证据。
事件响应演练参考准备、检测、响应、恢复、报告五阶段，验证安全控制而非只记录制度。
