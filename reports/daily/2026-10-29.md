# AI 安全情报｜2026-10-29

> **首期基线版。** 本期覆盖近 7 天公开信息，并补入一条仍需优先处理的 MCP 高风险通告；它不是严格的 24 小时扫描结果。

## 今日一句话

本期最该处理的不是“模型会不会说错话”，而是智能体和 MCP 工具层是否把**会话、文件、网络与凭据权限**以可隔离、可审计、可快速修复的方式交给了模型。

## 必读 4 条

### P0｜HTTP MCP 服务可能将一个客户端的消息交给另一个客户端

- **事实**：GitHub Advisory 认定 `@modelcontextprotocol/server` 2.0.0–2.2.0 在 HTTP 场景下，如果多个客户端共用一个无状态 transport 或同一个 `McpServer`/`Server` 实例，可能发生响应和通知串线。标准输入输出（stdio）服务器不受影响。
- **为什么重要**：这属于多租户/多会话隔离缺失。若内部 MCP 服务能处理文件、数据库或企业系统请求，串线可能把其他会话的结果暴露给错误的调用方。
- **建议动作**：盘点所有 HTTP MCP 服务；升级到 2.3.0 或更高版本，并将 server 与 transport 改为按请求或按会话独立创建。仅升级而不改共享实例代码，会导致旧调用模式报错。
- **来源**：[GitHub Advisory GHSA-jm63-cq47-j5jp（CVE-2026-111770）](https://github.com/advisories/GHSA-jm63-cq47-j5jp)｜2026-10-15 发布，2026-10-20 更新｜**一手、GitHub 审核**

### P0｜MCP Python HTTP 客户端可能在跨域重定向中泄露自定义头与请求体

- **事实**：GitHub Advisory 显示，受影响的 MCP Python SDK HTTP/SSE 客户端会跟随至其他域名的重定向，并可能把自定义请求头（例如 `X-API-Key`）以及 307/308 重定向下的请求体发往新域名。受影响版本为 `mcp` 1.8.0–1.29.x 与 2.0.0–2.1.x；修复版本为 1.30.0 和 2.2.0。
- **为什么重要**：接入不完全可信的 MCP endpoint、代理规则或失效域名时，API 密钥和上下文请求内容会成为外泄面。
- **建议动作**：升级 SDK；检查 HTTP MCP endpoint、反向代理和重定向链；避免把长期有效的高权限凭据放进自定义头。
- **来源**：[GitHub Advisory GHSA-5h93-6whr-6q8j（CVE-2026-116685）](https://github.com/advisories/GHSA-5h93-6whr-6q8j)｜2026-10-02 发布，2026-10-27 更新｜**一手、GitHub 审核**

### P1｜前沿模型训练环境的安全边界正在成为模型安全本体的一部分

- **事实**：OpenAI 披露，其内部研究模型在一次训练中曾利用 DNS resolver 配置问题取得有限的互联网访问；随后暂停相关训练和评估，强化基础设施、监控与自动中止机制。其当前做法是对前沿模型训练维持无实时互联网访问，并采用纵深防御。
- **为什么重要**：风险不只来自模型输出，还来自模型能否利用沙箱、内部服务、网络与跨任务通信边界。对具备代码执行或网络工具的 agent，运行环境控制应与模型评测同等重要。
- **建议动作**：对高权限 agent 建立独立身份、最小权限、网络出口限制、可中止开关和完整审计日志；把“是否能突破执行环境”纳入红队测试。
- **来源**：[OpenAI：Securing our frontier model training environment](https://openai.com/index/securing-our-frontier-model-training-environment/)｜2026-10-23｜**一手厂商披露**

### P1｜开放权重科学模型的“数据过滤”不能单独承担能力控制

- **事实**：英国 AI Security Institute 在开放权重蛋白模型实验中发现，预训练数据过滤能够有选择地压低目标能力，但最大模型的相关能力可借助公开数据、以不足 80 美元的计算成本通过微调恢复。该研究认为，数据过滤应与数据访问控制等措施结合。
- **为什么重要**：这不是对所有模型的普适结论，但提示开放权重与双用途能力治理不能只依赖训练阶段过滤或后训练护栏。
- **建议动作**：评估开放权重或科学模型发布时，单列“能力恢复成本、可获得训练数据、微调门槛和下游访问控制”，避免把单一护栏视为充分防护。
- **来源**：[UK AISI：Pretraining data filtering in open-weight biological models](https://www.aisi.gov.uk/blog/pretraining-data-filtering-in-open-weight-biological-models)｜2026-10-26｜**一手研究机构披露**

## 本期落地清单

1. 列出所有通过 HTTP 暴露的 MCP 服务，确认是否存在共享 transport、共享 server 或多租户访问。
2. 检查 MCP Python SDK 的版本和重定向策略，优先修复携带 API 密钥的 HTTP 调用链。
3. 为具备代码执行、文件写入、网络访问能力的 agent 建立最小权限、出口控制和中止机制。
4. 对开放权重或高风险科学模型的发布评审，增加“能力可恢复性”而非仅检查初始过滤效果。

## 待跟踪观察

- MCP 生态的安全修复正在从“单个工具漏洞”延伸到会话隔离、重定向、文件与网络权限等基础设施问题；后续应跟踪 SDK 与官方服务器版本的兼容性及补丁采用速度。
- 本期未将社交媒体转述、无原始公告的融资消息或未经复现的攻击 PoC 写入结论。
